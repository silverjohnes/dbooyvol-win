# DBooyvol → Windows: полный контекст разработки

Документ описывает macOS-версию DBooyvol настолько подробно, чтобы по нему вместе
с исходниками можно было собрать Windows-версию с тем же поведением. Он не заменяет
код: точные алгоритмы находятся в файлах, перечисленных в конце. Здесь — контракты,
состояния, форматы, сценарии и список мест, которые придётся заменить.

Версия на момент передачи: **1.0.128 (build 128)**. Тег `v1.0.125` относится к
более ранней сборке (1.0.125, build 125, коммит `2fa3b68`); правки после тега —
в коммитах `4128c34`, `79990c5`, `21c300d` (1.0.126), `0254536` (1.0.127) и
`cf7c598` (1.0.128). Bundle ID: `silver.dbooyvol`.

Документ обновлён после 1.0.125: **локальный фильтр результата удалён
полностью**, вместо него в статус-баре есть кнопка **«Результат (Tab)»**
(иконка `rectangle.split.2x1`, подсказка ровно `Результат (Tab)`), которая
переключает сетку и вертикальный просмотр строки; подсказки появляются через
**1,0 с** и рисуются собственным окном; **калькулятор удалён полностью**.
В 1.0.127 вертикальная строка стала одним выделяемым текстовым полотном:
`⌘A` выделяет всю строку, `⌘C` копирует, экспорт CSV/XML/XLSX доступен из
контекстного меню и статус-бара, а `⌘A` в сетке выделяет все ячейки.
В 1.0.128 Java-пакет sidecar переименован из `ru.evotor.sqldesk` в
`silver.dbooyvol`; `Main-Class` в `sidecar.jar` — `silver.dbooyvol.Main`.
Сводка изменений — в §16; если текст расходится с кодом, источником истины
является код.

### Как пользоваться этим документом

1. Сначала прочитать §2–§4 (архитектура, sidecar, файлы состояния).
2. Затем §5 и §16 — это актуальный UI-контракт, включая шесть новых функций.
3. §6–§8 — алгоритмы, которые нельзя потерять при портировании.
4. §12 — обязательные сценарии приёмки; §13 — уже собранные грабли.
5. §14 — карта исходников: по ней видно, какие файлы читать целиком.

Чистые алгоритмы `SQLCompletion` не зависят от AppKit и переносятся почти
дословно. Вся работа с состоянием результата — в `AppModel` и `ResultsView`;
это самые важные файлы для сетки и вертикального просмотра строки.

## 1. Что именно нужно воспроизвести

Продукт — настольный клиент SQL для PostgreSQL, Oracle, ClickHouse и SQLite:
дерево объектов, несколько вкладок со скриптами, редактор с подсветкой, выполнение
запроса через JDBC, история, таблица результатов, инспектор значения, экспорт и
редактирование данных.

Windows-версия обязана сохранить:

- подключения (включая SSH-туннель и Oracle EZ Connect/TNS/LDAP);
- дерево баз/схем/таблиц/представлений/столбцов с сохранением раскрытия;
- вкладки: создание, переименование, дублирование, перетаскивание, закрытие,
  привязку каждой вкладки к своему подключению, восстановление между запусками;
- редактор: подсветку, автодополнение скобок, комментарии, поиск, выделение,
  параметры `:name`, «умное выделение», тройной клик по `%`, а также подсказки
  столбцов и значений после `WHERE` / `AND` / `ON` / `ORDER BY`;
- выполнение выделения/всего скрипта/запроса под курсором, отмену, постраничную
  загрузку и «загрузить все»;
- сетку результатов: выделение ячеек/строк/столбцов, сортировку, изменение ширины,
  перетаскивание столбцов, поиск по результату, контекстное меню, инспектор
  значения, редактирование и вставку строк;
- вертикальный просмотр одной строки по `Tab` и кнопке «Результат (Tab)» в
  статус-баре: вся строка — одно выделяемое полотно, `⌘A` — весь текст, `⌘C` —
  копирование, экспорт CSV/XML/XLSX из контекстного меню и статус-бара;
- значок ключа в углу нумерации строк с подсказкой об уникальном ключе;
- задержку подсказок 1,0 с вместо системных ~2 с;
- копирование в 9 форматах и настраиваемую вставку;
- экспорт CSV/XML/XLSX, включая диалоги о неполных данных и о выделении;
- историю запросов с ограничением срока хранения;
- 22 языка интерфейса, включая украинский, который пока показывает русские тексты;
- все горячие клавиши и их переназначение;
- хранение паролей в защищённом хранилище ОС;
- сохранение значений строками от JDBC до файла/буфера, без потери точности и
  часового пояса.

### Что можно переиспользовать без изменений

- **Весь Java-sidecar** (`Sidecar/src/main/java/silver/dbooyvol/*.java`) —
  JDBC-движок, разбор `:name`, метаданные, редактирование, форматирование значений.
- **JDBC-драйверы** в `Resources/`: `postgresql.jar`, `sqlite-jdbc.jar`,
  `clickhouse-jdbc.jar`, `slf4j-api.jar`, `slf4j-nop.jar`, `antlr4-runtime.jar`.
  `ojdbc*.jar` пользователь указывает сам.
- **Форматы файлов состояния** (`profiles.json`, `tabs.json`, `columnWidths.json`,
  `history.jsonl`) — их можно читать на Windows, но путь другой.
- **Алгоритмы экспорта** (CSV/XML/XLSX) — их нужно портировать, они не завязаны
  на macOS, кроме `Compression` для deflate.
- **Новые чистые алгоритмы**: `Sources/Model/SQLCompletion.swift` (контекст и
  кандидаты автодополнения). Он использует только Foundation и переносится
  почти построчно.
- **Строки локализации** `Resources/*.lproj/Localizable.strings` — ключом является
  русский текст.

### Что придётся заменить

| macOS | Windows |
|---|---|
| SwiftUI + AppKit | WinUI 3 / WPF / Avalonia (рекомендуется WinUI 3 или Avalonia) |
| `NSTextView`, `NSTableView`, `NSOutlineView` | `RichEditBox`/ScintillaNET/AvalonEdit, DataGrid/ListView, TreeView |
| Keychain + Touch ID + CryptoKit AES-GCM | DPAPI/Credential Manager + Windows Hello + AES-GCM |
| `NSSavePanel`, `NSOpenPanel`, `NSAlert` | `FileSavePicker`, `FileOpenPicker`, `ContentDialog` |
| Carbon `UCKeyTranslate`, `NSEvent` | Win32 `ToUnicodeEx`, `KeyDown`/`PreviewKeyDown` |
| `NSFontManager` | `InstalledFontCollection` / `System.Drawing.Text` |
| `.lproj` + `NSLocalizedString` | `.resw`/`.resx` или собственный загрузчик `.strings` |
| `/usr/bin/ssh`, `/usr/bin/nc` | `ssh.exe` (OpenSSH for Windows) + `Test-NetConnection`/TCP-сокет |
| POSIX-пути, `~` | `%APPDATA%`, `%LOCALAPPDATA%`, `Environment.SpecialFolder` |
| XcodeGen/Xcode | MSBuild/CMake + упаковщик (MSIX или ZIP + ярлык) |
| `Process` + pipes | `System.Diagnostics.Process` + перенаправленные stdin/stdout |

Главное архитектурное решение: **Java-sidecar остаётся**. Меняется только нативный
слой. Это сохраняет совместимость SQL-поведения и драйверов.

## 2. Архитектура

```
┌──────────────────────────────┐        NDJSON по stdin/stdout        ┌────────────────────┐
│  Нативный UI (macOS/Windows) │ ───────────────────────────────────▶ │  sidecar.jar (JVM) │
│  вкладки, редактор, сетка    │ ◀─────────────────────────────────── │  JDBC, метаданные  │
└──────────────────────────────┘        одна строка = один JSON       └────────────────────┘
```

- Один долгоживущий JVM-процесс на всё приложение.
- Запуск: `java -Dfile.encoding=UTF-8 -Xss4m -jar sidecar.jar`.
- Java-пакет — `silver.dbooyvol`; точка входа и `Main-Class` в манифесте —
  `silver.dbooyvol.Main`. Исходники: `Sidecar/src/main/java/silver/dbooyvol/`.
- Рабочая директория не важна; jar и драйверы лежат рядом.
- Обмен — построчный NDJSON (UTF-8, `\n`), без Content-Length и без JSON-RPC
  обёртки `jsonrpc`.
- UI держит соответствие `id → continuation/promise`; ответы приходят в любом
  порядке.
- Запросы в разных вкладках выполняются параллельно: каждая вкладка имеет **своё**
  JDBC-соединение. Один профиль может быть открыт несколькими соединениями.
- Внутри одного соединения statements сериализуются (`connLock`).
- `cancel`, `cancelConn`, `count`, `updateRows`, `primaryKeys`, `tableMeta`
  выполняются на отдельных потоках, чтобы не стоять в очереди за выполняющимся
  запросом.
- `query` и `fetch` держат открытый `ResultSet` (курсор) до `done` или
  `closeCursor`. Максимум — 100 000 строк на курсор.

### Почему значения — строки

`Engine.value()` всегда возвращает `String` или `null`:

- `BigDecimal` → `toPlainString()` (без экспоненты и потери точности);
- `Timestamp`/`LocalDateTime` → ISO `yyyy-MM-ddTHH:mm:ss[.SSS]`;
- `OffsetDateTime`/`ZonedDateTime`/колонки WITH TIME ZONE → ISO с offset;
- `Date`/`Time` → ISO;
- `byte[]`/`Blob` → Base64;
- `Boolean` → `"true"`/`"false"`;
- `Clob` → текст до 1 000 000 символов, при обрезке добавляется `…`;
- массивы → `Arrays.deepToString`.

Windows-клиент не должен парсить числа в `double` и не должен конвертировать
время при получении. Единственное преобразование времени — **отображение**
timestamp в выбранном поясе (см. §6.4), исходное значение остаётся строкой.

### Ошибки

Ошибка всегда имеет форму:

```json
{"id":7,"ok":false,"error":{"message":"...","class":"SQLException","sqlState":"42P01","code":0}}
```

- `message` — сообщение корневой причины;
- `class` — простой класс корня;
- `sqlState`/`code` — из ближайшего `SQLException` в цепочке причин (до 6 уровней).

UI классифицирует потерю соединения не по тексту, а по:

- флагу `lost` (JVM завершился / sidecar не запущен);
- `sqlState` с префиксом `08`;
- запасным текстовым маркерам (для старых ответов).

При потере соединения `Session` один раз переподключается и повторяет statement.

## 3. Протокол sidecar

### 3.1. Формат

Запрос:

```json
{"id":1,"method":"query","params":{"connId":"c1","sql":"select 1","kind":"postgres","count":200,"params":{}}}
```

Успех:

```json
{"id":1,"ok":true,"result":{...}}
```

`id` — целое, уникальное в рамках клиента. `params` может отсутствовать.

### 3.2. Методы

#### `connect`

Параметры:

| Поле | Тип | Примечание |
|---|---|---|
| `kind` | `postgres`/`oracle`/`clickhouse`/`sqlite` | обязательно |
| `host` | string | |
| `port` | int | по умолчанию 5432/1521/8123/0 |
| `database` | string | для SQLite — путь к файлу |
| `user`, `password` | string | |
| `driverPath` | string | путь к jar или папке Instant Client |
| `url` | string | переопределение JDBC URL |
| `oracleSid` | bool | SID вместо service name |
| `oracleMode` | `easy`/`tns`/`ldap` | |
| `oracleAlias` | string | TNS-алиас или LDAP-сервис |
| `tnsAdmin` | string | каталог `network/admin` |
| `ldapHost`, `ldapPort`, `ldapContext`, `ldapSsl` | | LDAP/OID |
| `oracleAuthServices` | string | например `RADIUS` |

Результат:

```json
{"connId":"c1","serverVersion":"16.2","driver":"PostgreSQL JDBC Driver 42.7","user":"me"}
```

Особенности:

- Oracle без `driverPath` → ошибка с просьбой указать `ojdbc8.jar`/`ojdbc11.jar`.
- Если `driverPath` — папка Instant Client, из неё берутся `network/admin` и jar.
- `TNS_ADMIN` передаётся в свойствах соединения, а не через `System.setProperty`,
  чтобы профили не влияли друг на друга.
- Oracle: `oracle.jdbc.ReadTimeout=0`, `defaultNChar=true`,
  `timezoneAsRegion=false`, `v$session.program=DBooyvol`.
- PostgreSQL: `ApplicationName=DBooyvol`, `sslmode=prefer`, `connectTimeout=15`,
  `tcpKeepAlive=true`.
- ClickHouse: `socket_timeout=30000`, `connection_timeout=15000`, `compress=1`.
- SQLite: `jdbc:sqlite:<absolute path>`.
- После открытия: `autoCommit=false`, `readOnly=true` (где драйвер позволяет).
- Драйверы загружаются изолированным classloader; PostgreSQL/SQLite/ClickHouse —
  из jar рядом с sidecar.

#### `disconnect`

`{"connId":"c1"}` → `{"closed":true}`. Откатывает транзакцию, закрывает соединение
и все его курсоры.

#### `tree`

`{"connId":"c1","path":["schema","Tables"],"kind":"postgres"}` → `{"nodes":[...]}`.

Узел:

```json
{"id":"public|Tables","label":"Таблицы","kind":"folder","hasChildren":true,"primary":false}
```

Правила:

- `path=[]`: PostgreSQL/Oracle/ClickHouse — схемы; SQLite — один узел `main`.
  Для PostgreSQL скрываются `pg_*` и `information_schema`.
- `path=[schema]`: два узла — `Таблицы`, `Представления`.
- `path=[schema, folder]`: таблицы или `VIEW`/`MATERIALIZED VIEW`.
- `path=[schema, folder, table]`: столбцы; `detail` = тип с размером.
- `kind`: `schema`, `folder`, `table`, `view`, `column`.
- `primary` — текущая схема пользователя (для жирного начертания).

Ошибка метаданных откатывает транзакцию соединения (важно для PostgreSQL 25P02).

#### `query`

| Поле | Тип | Примечание |
|---|---|---|
| `connId` | string | |
| `sql` | string | один или несколько statements; выполняется как есть |
| `kind` | string | |
| `count` | int | размер первой страницы, по умолчанию 200 |
| `params` | object | значения `:name`; `null` → SQL NULL |

Результат с данными:

```json
{
  "queryId":"q2",
  "columns":[{"name":"id","type":"int8","className":"java.lang.Long","jdbcType":-5,"precision":19,"scale":0,"nullable":false,"table":"users","schema":"public","catalog":"db"}],
  "rows":[["1"],["2"]],
  "done":false,
  "truncated":false,
  "durationMs":12
}
```

Результат без данных:

```json
{"updateCount":3,"columns":[],"rows":[],"truncated":false,"durationMs":5}
```

- `count` зажимается в `1...100000`.
- `fetchSize` = 500 для Oracle, 1000 для остальных.
- `truncated=true`, когда курсор остановлен на `MAX_ROWS=100000`.
- При `done=true` курсор сразу закрывается.
- Если statement не вернул ResultSet — commit и `updateCount`.

#### `fetch`

`{"queryId":"q2","count":200}` → `{"rows":[...],"done":false}`.
Если курсор неизвестен — `rows:[]`, `done:true`.

#### `cancel`

`{"queryId":"q2"}` → `{"cancelled":true}`. Отменяет statement курсора.

#### `cancelConn`

`{"connId":"c1"}` → `{"cancelled":true}`. Отменяет активный statement соединения —
используется, пока `queryId` ещё не пришёл.

#### `count`

Считает полное число строк на **отдельном** коротком соединении:

```json
{"connId":"c1","sql":"SELECT count(*) FROM (\nselect ...\n) dbooyvol_count","kind":"postgres","params":{}}
```

→ `{"count":12345,"durationMs":40}`. `setQueryTimeout(600)`.
Клиент строит SQL только для SELECT/WITH/VALUES/TABLE, оборачивая **первый**
statement.

#### `primaryKeys`

`{"connId":"c1","catalog":"","schema":"public","table":"users"}`
→ `{"columns":["id"]}` (в порядке `KEY_SEQ`).

#### `tableMeta`

То же + результат:

```json
{
  "columns":[{"name":"id","type":"int8","size":19,"nullable":false,"primary":true}],
  "primaryKey":["id"],
  "primaryKeyName":"users_pkey"
}
```

#### `updateRows`

```json
{
  "connId":"c1","catalog":"","schema":"public","table":"users",
  "updates":[{"keys":{"id":"7"},"values":{"name":"Ann","age":null}}],
  "inserts":[{"name":"Bob","age":"30"}]
}
```

→ `{"updated":1,"inserted":1}`.

- Работает на отдельном соединении, чтобы не мешать открытому курсору.
- `UPDATE table SET col=? ... WHERE pk=?`; `NULL` в ключе → `IS NULL`.
- Значения биндятся по JDBC-типу колонки: boolean/bit, целые, decimal, float,
  date/time/timestamp/timestamptz, binary/BLOB (Base64), остальное — строка.
- Всё в одной транзакции; ошибка → rollback.
- Пустые `updates` и `inserts` → `{updated:0,inserted:0}`.

#### `closeCursor`

`{"queryId":"q2"}` → `{"closed":true}`. Закрывает ResultSet/Statement и коммитит
**только** соединение этого курсора.

#### `ping`

→ `{"pong":true}`.

### 3.3. Параметры `:name`

Разбор в `Engine.bindPlaceholders` и `SQLText.parameters`:

- `:name` → `?`;
- игнорируются строки `'...'`, идентификаторы `"..."`, `--` комментарии,
  `/* ... */`, PostgreSQL dollar-quotes `$tag$...$tag$`;
- `::type` и `:=` не считаются параметрами;
- имена сравниваются без учёта регистра (важно для Oracle);
- отсутствующее значение → SQL NULL (клиент обязан спросить все найденные имена);
- PostgreSQL: `setObject(i, value, Types.OTHER)`, чтобы сервер сам вывел тип;
- остальные: `setString`.

UI показывает модальный диалог «Параметры запроса»: по строке на параметр,
поле + чекбокс `NULL`; последние значения запоминаются **в памяти** по профилю.

## 4. Модель данных и файлы состояния

### 4.1. Расположение (macOS)

`~/Library/Application Support/DBooyvol/` с правами `0700`; файлы `0600`:

| Файл | Содержимое |
|---|---|
| `profiles.json` | массив профилей, pretty JSON, sorted keys |
| `profiles.bak.json` | предыдущая ревизия профилей |
| `tabs.json` | снимок вкладок |
| `columnWidths.json` | ширины по имени запроса |
| `history.jsonl` | по одной записи истории на строку, ISO-8601 даты |
| `secrets.json` | `account → "enc2:<keyid>:<base64>"` |
| `.master.key` | legacy, удаляется |

Windows-путь: `%APPDATA%\DBooyvol\` (Roaming) или `%LOCALAPPDATA%\DBooyvol\`.
Рекомендуется `%APPDATA%`, чтобы профили попадали в роуминг, а секреты — в
DPAPI текущего пользователя.

### 4.2. `profiles.json`

```json
[{
  "id":"UUID",
  "name":"Prod",
  "kind":"postgres",
  "host":"localhost",
  "port":5432,
  "database":"app",
  "user":"me",
  "driverPath":"",
  "jdbcUrl":"",
  "oracleSid":false,
  "ssh":{"enabled":false,"host":"","port":22,"user":"","keyPath":""},
  "readOnly":true,
  "savePassword":true,
  "oracleMode":"easy",
  "oracleAlias":"",
  "tnsAdmin":"",
  "ldapHost":"",
  "ldapPort":389,
  "ldapContext":"",
  "ldapSSL":false,
  "oracleAuthServices":"",
  "instantClientDir":""
}]
```

- Все поля, кроме `id`, могут отсутствовать — используются значения по умолчанию.
- `savePassword` отсутствует в старых профилях → считается `true`.
- `jdbcUrl` с логином/паролем запрещён: UI предупреждает, что они попадут в файл
  открытым текстом.
- `readOnly` сейчас информационное; sidecar всё равно открывает `readOnly=true`,
  а запись идёт отдельным соединением.

### 4.3. `tabs.json`

```json
{"tabs":[{
  "id":"UUID","title":"Запрос 1","text":"select 1;","filePath":null,
  "customTitle":false,"isDirty":false,
  "selectionLocation":0,"selectionLength":0,"profileID":"UUID"
}],"activeID":"UUID"}
```

- `customTitle=true` — имя задано вручную, не переводится и не переименовывается.
- Автоимена вида «Запрос N» при смене языка пересоздаются; номер сохраняется.
- `profileID=null` — вкладка следует за выбранным в дереве подключением; при
  первом запуске запроса привязка фиксируется.

### 4.4. `columnWidths.json`

```json
{"Запрос 1":{"id":80,"name":220}}
```

Ключ — `QueryResult.queryName` (имя вкладки на момент выполнения). Ширины
сохраняются с задержкой 0,5 с и принудительно при выходе.

### 4.5. `history.jsonl`

Одна строка — один `HistoryEntry`:

```json
{"id":"UUID","date":"2026-11-26T12:00:00Z","profile":"Prod",
 "sql":"select ...","durationMs":12,"rowCount":2,
 "error":null,"columns":["id"],"rows":[["1"],["2"]]}
```

- Хранится до 2000 записей в памяти; на диск пишутся все, но старые удаляются
  при загрузке по сроку хранения.
- В историю попадают первые 200 строк, каждая ячейка обрезается до 1000 символов.
- Срок по умолчанию 30 дней; `0` — бессрочно. Уменьшение срока сразу перезаписывает
  файл без старых записей.
- Ошибка запроса сохраняется в `error`.

### 4.6. Секреты

macOS: `secrets.json` + мастер-ключ 256 бит в Keychain
(`service=silver.dbooyvol.secret-store`, `account=master-key-v2`). Шифрование
AES-256-GCM; формат `enc2:<keyid>:<base64(nonce+ciphertext+tag)>`.

Доступ к мастер-ключу подтверждается системным запросом **Touch ID** (на Mac
без биометрии — паролем пользователя) один раз за запуск приложения
(`LAContext.evaluatePolicy(.deviceOwnerAuthentication)`). После подтверждения
все сохранённые пароли читаются без отдельных запросов.

Критично для надёжности:

- ошибка чтения Keychain (`errSecAuthFailed`, `errSecInteractionNotAllowed`,
  `errSecNotAvailable`) **не** означает «ключа нет»; её нельзя путать с
  `errSecItemNotFound`;
- новый ключ создаётся только если элемент действительно отсутствует **и**
  `secrets.json` пуст; при наличии шифротекста отсутствие ключа — это
  `keyMissing`/`wrongKey`, а не повод перезаписать элемент;
- обычное чтение никогда не делает `SecItemUpdate`; замена ключа — только
  явная операция «Перешифровать пароли»;
- если ключ всё же изменился, показывается один общий диалог для всех
  пострадавших подключений, а не отдельная ошибка на каждое;
- `enc2:<keyid>` позволяет сравнить ключ с шифротекстом без расшифровки.

Windows-реализация:

- мастер-ключ 32 байта, защищённый DPAPI (`CryptProtectData` с
  `CRYPTPROTECT_LOCAL_MACHINE` **не** использовать; только пользовательский
  контекст);
- либо сам пароль в Credential Manager (`CredWrite`/`CredRead`) с target
  `DBooyvol/<profile UUID>`;
- AES-GCM можно оставить, чтобы `secrets.json` имел тот же формат;
- привязка к пользователю Windows, а не к подписи приложения;
- перед чтением — **Windows Hello** (`UserConsentVerifier` или
  `KeyCredentialManager`), один раз за запуск; без биометрии — PIN/пароль;
- операции: сохранить/загрузить/удалить, «перешифровать все», очистить legacy;
- различать «элемент не найден» и «доступ запрещён»; при ошибке доступа
  показывать системный запрос и никогда не создавать новый ключ поверх
  существующего;
- при смене ключа — один общий диалог повторного ввода паролей.

Пароль в открытом виде живёт только до `connect`; после — уничтожается.

### 5.4. Редактор SQL

- `NSTextView` в `NSScrollView`, без rich text, с undo, без автозамен.
- Шрифт моноширинный, размер 14 по умолчанию, отступ 12×12.
- Подсветка SQL: ключевые слова, строки, числа, комментарии, параметры.
- Подсветка пересчитывается через 60 мс после ввода, с сохранением каретки.
- Автодополнение скобок:
  - `(` → `()`, `[` → `[]`, `{` → `{}`, каретка внутри;
  - если следующий символ — нужная закрывающая, она не дублируется, каретка
    перешагивает;
  - закрывающая скобка перед такой же закрывающей — шаг вправо.
- Вертикальное перемещение сохраняет желаемую колонку (даже через короткие строки).
- `Ctrl` + колесо и pinch меняют размер шрифта.
- Строка состояния: `строка : колонка : смещение`.

#### Автодополнение после WHERE / AND

Собственного popup у AppKit нет — в `SQLTextView` (см. `SQLCompletionPopup`)
сделан borderless `NSPanel` со списком, который не забирает фокус у редактора.
Триггер — каждое изменение текста/каретки, если каретка стоит в подходящем
месте. Точные правила (`Sources/Model/SQLCompletion.swift`):

- Кандидаты-столбцы показываются после последнего ключевого слова `WHERE`,
  `AND`, `OR`, `ON`, `HAVING`, `SET`, `ORDER BY`, `GROUP BY` — но только пока
  после него не началось новое слово. После `WHERE name ` (слово уже набрано и
  пробел) список не открывается: следующим токеном ожидается оператор.
- Кандидаты-значения показываются после `column =`, `!=`, `<>`, `>`, `<`,
  `>=`, `<=`, `LIKE`, `ILIKE`, `IN (`; колонка берётся из текста до оператора.
  Значения — различные непустые значения этой колонки из **уже загруженного**
  результата, максимум 500; числовые вставляются как есть, строковые — в
  одинарных кавычках с удвоением `'`.
- Столбцы: сначала колонки текущего результата, затем алиасы из SELECT-списка
  текущего скрипта (парсер понимает `AS alias` и «последний идентификатор»,
  пропускает `*` и `t.*`). Дубликаты убираются без учёта регистра, максимум 60.
- Фильтрация по префиксу: регистронезависимо, `hasPrefix` или `contains`;
  кавычки в начале префикса игнорируются.
- Внутри строкового литерала и после `--` в строке подсказки не показываются;
  также не показываются после `SELECT`, `FROM`, `JOIN`, `VALUES`, `RETURNING`,
  `UNION`, `LIMIT`, `OFFSET` и внутри подзапроса после `IN (SELECT`.
- Клавиши при открытом списке: ↑/↓ — выбор, Enter/Tab — вставить, Esc —
  закрыть. Вставка заменяет только диапазон набираемого слова (не весь текст
  до каретки). После вставки список не открывается повторно на той же позиции.
- Клик по строке списка тоже вставляет. Список закрывается при клике в текст,
  прокрутке и потере фокуса редактором.
- Позиция — под каретой; если снизу нет места, список раскрывается вверх.

Поиск в скрипте (`⌘F`, фокус в редакторе):

- панель над редактором, плейсхолдер «Найти в скрипте — раскладка не важна»;
- подсветка всех совпадений жёлтым, переход к первому;
- Enter/Shift+Enter — следующий/предыдущий, счётчик;
- поиск учитывает раскладку (см. §6.1).

### 5.5. Результаты

- Кастомный `NSTableView` + замороженный gutter с номерами строк (ширина 52).

  `Уникальный ключ: schema.table(col, …)` по метаданным таблиц; если ключ
  неизвестен — `Уникальный ключ не определён`. Номера строк остаются.
- Задержка появления подсказок — **1,0 с** и собственное окно
  `TooltipCenter` (не системный tooltip). Это относится ко всем подсказкам,
  включая заголовки, gutter, статус-бар, позицию каретки и часовой пояс.
- Строка 22 pt, чередующийся фон, без сетки.
- NULL отображается серым текстом `NULL`.
- Числовые колонки выравниваются вправо; сортировка числовая.
- Ссылки `http/https` показывают кнопку открытия.
- Заголовок: имя, при включении — тип; сортировка по клику на стрелку; первая
  сортировка по убыванию, затем по возрастанию.
- Ширина: перетаскивание разделителя; двойной клик — автоподбор.
- Автоширина по содержимому, но не более `maxAutoColumnWidth` (280).
- Перетаскивание заголовка меняет визуальный порядок; можно тащить блок
  выделенных столбцов; порядок живёт до следующего выполнения.
- Выделение:
  - клик — ячейка; drag — прямоугольник;
  - клик по номеру строки — строка; ⌘/Ctrl — добавить, Shift — диапазон;
  - клик по заголовку — столбец; ⌘/Ctrl — добавить, Shift — диапазон;
  - угол над номерами — весь результат;
  - текущая ячейка обведена оранжевой рамкой.
- `Tab` при фокусе в сетке открывает **вертикальный просмотр одной строки**
  (см. §16.5); повторный `Tab` возвращает сетку.
- При прокрутке до низа (60 pt до конца) автоматически загружается следующая
  страница.
- В статус-баре: «Загрузить ещё», «Загрузить все» (пока курсор не закрыт).
- Поиск по результату (`⌘F` при фокусе в таблице): по всем загруженным ячейкам,
  раскладка не важна, счётчик, Enter/Shift+Enter, подсветка. Скан >40 000 ячеек —
  в фоне; широкие результаты делятся на потоки.
- Контекстное меню: Копировать, Копировать… (9 форматов), Значение,
  Вставить, Вставить…, Экспорт (CSV/XML/XLSX), Открыть в…
  (Excel/Браузер/Другое).
- Подсказка заголовка: `Столбец: name TYPE [NOT NULL]`, уникальный ключ, таблица.
- Ошибка запроса — оранжевый баннер над результатом с SQLState/code.
- Во время выполнения — полупрозрачная карточка со спиннером, не перехватывает
  клики.

### 5.6. Редактирование результата

- Двойной клик по ячейке (или начало ввода) открывает inline-редактор.
- Изменение хранится в памяти; снизу появляется панель «Сохранить»/«Отменить».
- `originalRows` хранит исходные значения по стабильному `rowID`.
- Вставка из буфера ниже последней строки создаёт новые строки (`insertedRowIDs`).
- «Сохранить»:
  - все изменения должны относиться к одной таблице;
  - нужен первичный ключ, и его колонки должны быть в результате;
  - UPDATE по исходным PK, INSERT для новых строк;
  - ошибка показывается в панели, изменения остаются.
- «Отменить» восстанавливает исходные строки, удаляет вставленные, через 2 с
  панель исчезает.
- Переименование/сортировка/подгрузка не должны терять `rowID`.

### 5.7. Инспектор значения

Правая панель шириной 240…620 (идеал 340). В этом слоте показывается только
инспектор значения; калькулятора в приложении больше нет.

- заголовок «Значение · <колонка>», шестерёнка, закрытие;
- тип определяется автоматически: JSON, XML, binary, text; можно переопределить;
- меню: перенос строк, автоформат, компактный вид, кодировка (UTF-8, UTF-16,
  Windows-1251, CP866, ISO-8859-1, …);
- JSON форматируется с отступами; XML — с отступами; binary — hex-дамп + попытка
  текстовой расшифровки;
- футер: строка, тип (клик — копировать тип), «Копировать», «Сохранить…»;
- сохранение пишет UTF-8; для бинарных — исходные байты, если удалось декодировать
  Base64;
- панель следует за текущей ячейкой, пока открыта.

   старые пароли из связки ключей».

6. **Данные в результате** — шрифт, размер, тип в заголовке/подсказке, автоширина,

8. **Загрузка данных** — строк на страницу.

### 5.11. Редактор подключения

Лист 640×780 (SQLite — 540):

- имя, тип, порт по умолчанию;

### 5.12. Диалоги

## 6. Алгоритмы, которые легко потерять при портировании

### 6.1. Поиск без учёта раскладки

`SearchMatcher`:

- й↔q, ц↔w, у↔e, к↔r, е↔t, н↔y, г↔u, ш↔i, щ↔o, з↔p, х↔[, ъ↔],
  ф↔a, ы↔s, в↔d, а↔f, п↔g, р↔h, о↔j, л↔k, д↔l, ж↔;, э↔',
  я↔z, ч↔x, с↔c, м↔v, и↔b, т↔n, ь↔m, б↔,, ю↔.;
- запрос превращается в варианты: как есть и в другой раскладке;
- сравнение без учёта регистра;
- `TextLanguage` определяет преобладающий алфавит, чтобы предпочитать результаты
  на языке запроса;
- используется в Quick Open, поиске по скрипту и по результату.

### 6.2. Умное выделение

При открытии вкладки/фокусе редактора (если включено):

1. Найти первое ключевое слово `WHERE` вне строк/комментариев/dollar-quotes.
2. Внутри его клаузы найти первый непустой одинарный литерал.
3. Остановиться на `GROUP/ORDER/HAVING/LIMIT/OFFSET/FETCH/UNION/EXCEPT/INTERSECT/
   RETURNING/WINDOW/CONNECT/START/MODEL` или `;` на нулевой глубине.
4. Если перед литералом оператор `LIKE`/`ILIKE` — срезать ведущие/хвостовые `%`
   и `_`.
5. Если включено «Только при поиске», применять только для вкладки, открытой
   через Quick Open.
6. Применять с задержкой один тик run loop, чтобы клик мышью не сдвинул каретку.

### 6.3. Тройной клик

Приоритет:

1. Содержимое кавычек на строке каретки (без кавычек); для LIKE-паттерна срезать
   `%`/`_`.
2. Содержимое самых внутренних скобок, охватывающих каретку; игнорировать строки,
   `--` и `/* */`.
3. Текст между ближайшими `%` слева и справа на той же строке (для `%ПРИЛА%`);
   сами `%` не выделяются.

Если после срезания не осталось текста — вернуть исходный диапазон.

### 6.4. Отображение времени

- Конвертируются только колонки, чей тип содержит `TIMESTAMP`/`DATETIME`.
- Строка должна быть ISO-подобной: `YYYY-MM-DD[T ]HH:MM:SS[.fraction][Z|±HH[:MM]]`.
- Без offset/Z значение считается **UTC** (так хранят целевые БД).
- Перевести в выбранный пояс, вывести `YYYY-MM-DD HH:MM:SS`.
- Миллисекунды показывать, только если дробная часть ненулевая.
- Чистые дата/время не конвертируются.
- В статус-баре — короткий код пояса (ГОН, МСК, …), переведённый.

### 6.5. Комментарии

`⌘/`:

- комментарий — `--` сразу после отступа, без пробела;
- если все непустые строки выделения уже начинаются с `--` — снять;
- выделение, заканчивающееся на начале строки, не захватывает следующую;
- каретка/выделение сдвигаются на число добавленных/удалённых символов.

`⌘⇧/` (по маркеру):

- маркер = `--` + суффикс (по умолчанию `--!#`);
- обрабатываются все строки файла, оканчивающиеся маркером;
- строка только из маркера не считается помеченной;
- если все помеченные уже закомментированы — снять, иначе поставить;
- пустой суффикс отключает действие.

### 6.6. Statements и параметры

`SQLText.statements` делит по `;`, учитывая:

- `'...'` и `"..."` с удвоением кавычек;
- `--` до конца строки;
- `/* ... */`;
- PostgreSQL `$tag$...$tag$`.

`statement(at:)` возвращает statement, содержащий каретку; если каретка вне —
последний.

### 6.7. Статусы выполнения

- «Выполняется…»
- «Готово. Строк: N [из M] · X мс»
- «Готово: изменено строк N · X мс»
- «Строк: N+» пока неизвестно, есть ли ещё
- «Строк: N из M»
- «Отмена…», «Отменено», «Ошибка»
- «Загружено N строк…», «Загрузка всех строк…»
- «Экспортировано: file.csv»
- «Скопировано: N строк»
- «Вставлено: N строк»
- «Ячейка изменена — нажмите «Сохранить», чтобы записать в БД»
- «Сохранено: N строк, M ячеек»

Точные шаблоны — в `AppModel.runStatus` и `scripts/localize.py`.

### 6.8. Подсчёт общего числа строк

- Только для row-returning statement (`SELECT`, `WITH`, `VALUES`, `TABLE` после
  комментариев).
- Только если `!done || truncated`.
- SQL: `SELECT count(*) FROM (\n<первый statement без ;>\n) dbooyvol_count`.
- Считается в фоне после показа первой страницы, на отдельном соединении.
- Результат применяется, только если это всё ещё тот же результат/вкладка.

## 7. Копирование, вставка, экспорт

### 7.1. Копирование

Настройки по умолчанию: без заголовков и номеров строк, значения в кавычках при
необходимости, разделитель `\t`, строки `\n`, кавычка `"`, формат `display`.

Девять форматов контекстного меню:

- CSV;
- DbUnit;
- HTML;
- JSON;
- Markdown;
- SQL (`INSERT INTO ...`);
- исходный код (`String[][]`);
- TXT;
- XML.

Форматы значений:

- **Display** — как в сетке;
- **Editable** — `T` между датой и временем заменён пробелом;
- **Database native** — boolean → `t/f` или `1/0`, binary → `\x...`/`0x...`.

При `copyAsHTML` в буфер дополнительно кладётся HTML-таблица.

### 7.2. Вставка

- Разбирает текст с учётом разделителей и кавычек; `ignoreQuotes` отключает
  кавычки; пустые значения → NULL при `insertNulls`.
- `insertMultipleRows=false` вставляет только первую строку.
- Начало — первая выделенная строка/столбец.
- Выход за последнюю строку создаёт новые строки.
- Изменения не пишутся в БД до «Сохранить».

### 7.3. CSV

- RFC 4180: заголовок, `\r\n`, разделитель `,`, `nullValue=""`.
- Кавычки, если значение содержит разделитель, `"`, `\n`, `\r`; `"` удваивается.
- Значения — ровно те строки, что в результате.

### 7.4. XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<result rows="N">
  <columns><column name="id" type="int8" /></columns>
  <rows>
    <row><col name="id" type="int8">1</col></row>
    <row><col name="x" type="text" null="true" /></row>
  </rows>
</result>
```

Экранируются `& < > " '`; управляющие символы (кроме tab/LF/CR) → `&#xNN;`.

### 7.5. XLSX

- Минимальный OOXML, собирается вручную.
- Все ячейки — `inlineStr`, чтобы сохранить ведущие нули, 20-значные ID и текст.
- Ограничение ячейки 32767 символов; управляющие символы удаляются.
- Заморожена первая строка; ширины 8…60 по заголовку и первым 200 строкам.
- Лист называется «Результат» (переведённый), недопустимые символы удалены,
  максимум 31 символ.
- ZIP: deflate, если короче, иначе store; UTF-8 имена, DOS-дата.

### 7.6. Логика экспорта

1. Нет колонок → ошибка «Нет данных для экспорта».
2. Кнопки внизу/меню экспортируют **все** данные.
3. Если выбрана только часть и запрошен экспорт всех данных → диалог
   «Выделена часть данных».
4. Если загружены не все строки → диалог «Загружены не все данные».
   «Загрузить полностью» догружает страницами по `max(pageSize, 1000)` до 100 000.
5. Контекстное меню с выделением экспортирует выделение **без** вопроса.
6. Контекстное меню без выделения ведёт себя как экспорт всех данных.
7. Имя файла: `query-<ISO8601 с : → ->.<ext>`.
8. Запись в фоне; статус «Экспортировано: …» или ошибка.

## 10. Сборка macOS (как есть)

```bash
./Sidecar/build.sh          # javac --release 11 → Resources/sidecar.jar
xcodegen generate           # project.yml → DBooyvol.xcodeproj
make build                  # bump-build + Debug
make run
make release                # bump-build + Release
```

- `make bump-build` увеличивает `build-number.txt`, `CURRENT_PROJECT_VERSION`,
  `CFBundleVersion`, `MARKETING_VERSION = 1.0.<build>`.
- JDK 11+ обязателен.
- `project.yml`: macOS 13+, Swift 5, `silver.dbooyvol`, Personal Team
  `VWLZA3FPJX`, Release с hardened runtime.
- Релиз: `xcodebuild ... -configuration Release`, затем ZIP приложения
  (`ditto -c -k --keepParent`), тег, GitHub Release.
- `scripts/sign.sh` — Developer ID + notarization (сейчас не основной путь;
  используется Personal Team).
- Проверка: `--dump-menus` печатает меню с key equivalents; `--snapshot <png>`
  выполняет запрос и снимает окно.

### Windows-сборка (рекомендация)

1. **UI**: WinUI 3 (Windows App SDK) или Avalonia. WinUI ближе к нативному виду,
   Avalonia проще с кастомной сеткой и кроссплатформенностью.
2. **Sidecar**: оставить `sidecar.jar`; собрать его тем же `javac --release 11`.
   Варианты поставки:
   - требовать установленную JRE 11+ и настройку пути (как `javaPath` сейчас);
   - либо приложить `jlink`-runtime и запускать `runtime\bin\java.exe`.
3. **Драйверы**: положить рядом с jar; путь к Oracle `ojdbc` — в профиле.
4. **Процесс**: `ProcessStartInfo` с `RedirectStandardInput/Output/Error`,
   `StandardOutputEncoding = UTF8`, построчное чтение, `Idle`-таймаут не нужен.
5. **Секреты**: DPAPI + AES-GCM; хранить в `%APPDATA%\DBooyvol\secrets.json`.
6. **SSH**: `ssh.exe` из Windows OpenSSH:
   `ssh -N -o ExitOnForwardFailure=yes -o BatchMode=yes -o ConnectTimeout=10
   -o StrictHostKeyChecking=accept-new -o ServerAliveInterval=30
   -L 127.0.0.1:<port>:<host>:<port> user@host`.
   Свободный порт — через `TcpListener(IPAddress.Loopback, 0)`.
   Проверка готовности — TCP-подключение к localhost:port (аналог `nc -z`).
7. **Упаковка**: MSIX (желательно) или ZIP + `.cmd`/ярлык. Подпись — обычный
   code signing certificate; SmartScreen будет предупреждать без подписи.
8. **Обновления**: не реализованы; можно добавить позже.

## 12. Тестирование и приёмка

### 12.1. Изоляция тестов

Не трогать пользовательские `profiles.json`, `tabs.json`, открытые запросы и
`«Прила.sql»`. Для прогонов:

- отдельный `HOME`/`APPDATA` (macOS: `CFFIXED_USER_HOME=/tmp/.../home`);
- macOS: переменная `DBOOYVOL_SUPPORT_DIR=/tmp/.../support` перенаправляет весь
  каталог данных (`profiles.json`, `tabs.json`, `columnWidths.json`,
  `history.jsonl`, секреты) в изолированную папку; на Windows аналог —
  `%APPDATA%\DBooyvol` с отдельным пользователем/профилем ОС;
- отдельные `profiles.json`, `tabs.json`, `columnWidths.json`, `history.jsonl`;
- запуск нового экземпляра (`open -n` на macOS; отдельный процесс на Windows);
- SQLite-фикстура как основная БД для быстрых тестов: файл `.db` + профиль
  `kind: sqlite` с `savePassword: false` — пароль не запрашивается, шифрование
  не нужно.

### 12.2. Обязательные сценарии

1. **Подключения**: PostgreSQL, SQLite, ClickHouse; Oracle — при наличии драйвера.
   Проверить тест соединения, ошибку без драйвера, SSH-туннель.
2. **Дерево**: схемы → таблицы/представления → столбцы; раскрытие сохраняется
   после перезапуска; двойной клик открывает `SELECT *`.
3. **Вкладки**: создать, переименовать, дублировать, перетащить, закрыть грязную,
   восстановить после перезапуска; у каждой своё подключение.
4. **Редактор**: подсветка, скобки, комментарии `⌘/` и `⌘⇧/`, `⌘F`, тройной клик
   по `'...'`, `(...)`, `%...%`; `⌘↩` и `⌘R`; запрос под курсором.
5. **Параметры**: `:name`, `::cast`, `:=`, параметр в строке/комментарии, NULL.
6. **Результат**: первая страница, автодогрузка, «Загрузить ещё/все», общий счётчик,
   сортировка, ширины, перетаскивание столбцов, выделение мышью/⌘/Shift.
7. **Поиск**: по скрипту и результату в русской и английской раскладке; счётчик;
   переход вперёд/назад.
8. **Копирование**: все 9 форматов, настройки, HTML в буфере.
9. **Вставка**: несколько строк, кавычки, NULL, новые строки, отмена.
10. **Редактирование**: изменение ячейки, сохранение по PK, ошибка без PK,
    несколько таблиц, INSERT новой строки.
11. **Экспорт**: CSV/XML/XLSX; выделение; неполные данные; «загрузить полностью»;
    открыть XLSX в Excel/LibreOffice; проверить ведущие нули и 20-значные ID.
12. **История**: запись, поиск, открытие в новой вкладке, срок хранения, очистка.
13. **Значение**: JSON, XML, бинарные, кодировки, копирование, сохранение.
14. **Языки**: смена языка → перезапуск; русский, английский, украинский
    (русские тексты), RTL (арабский).
15. **Горячие клавиши**: значения по умолчанию, переназначение, конфликт,
    сброс, работа в русской раскладке.
16. **Секреты**: сохранить пароль, перезапуск, подключение без повторного ввода;
    «не сохранять» → запрос при подключении; «перешифровать».
17. **Устойчивость**: убить JVM → приложение не падает, следующее действие
    перезапускает sidecar; потеря соединения → один retry.
18. **Фильтра нет**: ни панели, ни поля, ни кнопки фильтра, ни пункта меню, ни
    настройки; SQL и строки результата не меняются локальными условиями.
19. **Вертикальная строка**: кнопка «Результат (Tab)» в статус-баре (иконка
    `rectangle.split.2x1`, подсказка ровно `Результат (Tab)`) и `Tab` в сетке
    показывают выбранную строку (по умолчанию первую), заголовок `Строка №N`,
    слева имена колонок, справа значения, `NULL` серым; повторное нажатие
    возвращает сетку; переключать можно **неограниченно**, фокус остаётся в
    результате и не уходит в список подключений; `Tab` в полях
    редактора/поиска не переключает вид. Текст строки выделяется мышью
    поперёк колонок, `⌘A` выделяет всё, `⌘C` копирует; в контекстном меню и в
    статус-баре доступен экспорт CSV/XML/XLSX, как в сетке; `⌘A` в сетке
    выделяет все ячейки.
20. **Калькулятор удалён**: ни кнопки «Кальк», ни пункта «Калькулятор» в
    контекстном меню/меню «Вид», ни правого слота; инспектор значения работает
    один.
21. **Автодополнение SQL**: `WHERE `, `AND `, `ORDER BY `; фильтрация по
    префиксу; после `column =` — значения из результата; внутри `'...'` и после
    `--` подсказок нет; Enter/Tab вставляют, Esc закрывает; после `WHERE name `
    список не открывается.
22. **Ключ**: в углу нумерации строк значок ключа; подсказка показывает
    уникальный ключ для таблицы с PK и «не определён» без PK; номера строк
    остаются.
23. **Подсказки**: задержка появления ~1,0 с, а не ~2 с; подсказка есть у
    каретки, часового пояса, статуса, точки подключения, профиля, заголовков,
    gutter, кнопки «Результат (Tab)» и кнопок экспорта CSV/XML/XLSX; исчезает
    при уходе курсора, клике, прокрутке и наборе текста; не остаётся висеть,
    если событие ухода курсора потерялось.

### 12.3. Критерии готовности Windows-версии

- Все пункты §12.2 проходят.
- Значения в сетке и экспорте совпадают с macOS-версией байт-в-байт (кроме
  перевода строк в CSV/XLSX, где формат фиксирован).
- XLSX открывается без предупреждений, все значения — текст.
- Русская раскладка не ломает ни одну горячую клавишу.
- Пароли не попадают в логи, `profiles.json` и URL.
- Приложение работает при отсутствии Java с понятной ошибкой и настройкой пути.
- Нет обращений к пользовательским файлам вне `%APPDATA%\DBooyvol` без выбора
  пользователя.

## 13. Подводные камни

1. **Не парсить значения в числа.** `BigDecimal`, 20-значные ID, ведущие нули —
   только строки.
2. **Не конвертировать timestamp при получении.** Только при отображении; иначе
   двойной сдвиг пояса.
3. **`NULL` ≠ пустая строка.** В сетке `NULL` серый, в CSV пустой, в XML
   `null="true"`, в XLSX пустая ячейка.
4. **`queryId` живёт до `done`.** После `done` курсор закрыт; `fetch` вернёт пусто.
5. **`count` не должен идти по соединению с открытым курсором.** Sidecar уже
   открывает отдельное; на клиенте не переиспользовать основную сессию для счёта.
6. **Один statement на `query`.** Если пользователь выделил несколько — sidecar
   выполнит как есть; драйверы ведут себя по-разному. Не «оптимизировать» без
   проверки.
7. **`SELECT *` из дерева** должен быть `SELECT * FROM schema.table;` с
   кавычками, если нужно; текущая реализация формирует по `schema.table`.
8. **Oracle `TNS_ADMIN`** — только в свойствах соединения, иначе протечёт между
   профилями.
9. **PostgreSQL после ошибки метаданных** — rollback, иначе 25P02.
10. **`cancelConn`** нужен, пока `queryId` ещё не получен (долгий парсинг/старт).
11. **Сортировка локальная**, только по загруженным строкам; не путать с ORDER BY.
12. **Ширины столбцов** привязаны к имени запроса; переименование вкладки должно
    переносить записи.
13. **`rowID`** — стабильный UUID; сортировка/подгрузка обязаны переставлять его
    вместе со строкой, иначе редактирование попадёт не в ту строку.
14. **Редактирование join'а** запрещено, если затронуты разные таблицы.
15. **Вставка ниже данных** — это INSERT, а не UPDATE.
16. **Экспорт «все данные»** при частичном выделении должен спросить, иначе
    пользователь молча получит не то.
17. **XLSX**: inline strings, лимит 32767, запрещённые control-символы.
18. **CSV**: `\r\n`, кавычки только при необходимости.
19. **Поиск по результату** идёт по загруженным строкам, не по всей БД.
20. **Quick Open** ищет по первым 30 000 символам, не по всему файлу — это
    осознанно.
21. **Украинский = русский**; не «исправлять» без решения.
22. **`«Прила.sql»` не трогать.**
23. **Personal Team / подпись**: на Windows это неактуально, но не менять bundle
    ID/имена файлов состояния без миграции.
24. **Пути**: `~` раскрывать; на Windows `%USERPROFILE%`, `%APPDATA%`.
25. **Кодировка**: весь обмен и файлы — UTF-8; Java запускать с
    `-Dfile.encoding=UTF-8`.
26. **`NSLocalizedString` fallback**: на Windows обязательно возвращать ключ, а
    не пустую строку.
27. **Формат `%@`**: при переводе на `{0}` не потерять аргументы; лучше оставить
    свою мини-функцию форматирования.
28. **`ssh` на Windows** может быть не установлен; показать понятную ошибку и
    ссылку на установку OpenSSH Client.
29. **DPAPI** привязан к пользователю; при переносе `secrets.json` на другую
    машину пароли не расшифруются — это ожидаемо.
30. **Ошибка доступа к хранилищу ключа — не «ключа нет»**. Один раз это уже
    привело к перезаписи мастер-ключа и потере сохранённых паролей: новый ключ
    создавался после неудачного чтения. Создавать ключ можно только при
    `not found` и пустом `secrets.json`; при `access denied` — показать
    системный запрос, при `wrongKey` — общий диалог повторного ввода.
31. **Не логировать SQL с паролями** и содержимое `secrets.json`.
32. **Локального фильтра больше нет.** `displayedRowCount` равен числу строк
    результата, `dataRow(forDisplayRow:)` — тождественная функция. Не
    добавляйте фильтр обратно «по привычке»: условия задаются в SQL.
33. **`result.rows`/`rowIDs` — единственный источник строк.** Сортировка и
    подгрузка меняют порядок/состав результата, но не создают параллельного
    списка видимых индексов.
34. **Смена вкладки и новый запуск не должны воскрешать фильтр.** Никаких
    `filtersByTab`, `resultFilterText` и debounce-пересчёта в новой версии нет.
36. **Автодополнение не должно вставлять текст в строковые литералы/комментарии
    и не должно заменять весь текст до каретки.** Заменяется только диапазон
    текущего слова; после вставки список не переоткрывается на той же позиции.
37. **Значения для автодополнения — из загруженного результата, не из БД.**
    Максимум 500 различных; строковые — в кавычках, `'` удваивается; числовые
    без кавычек. Колонка ищется по имени без префикса таблицы.
38. **`Tab` нельзя делать глобальным акселератором.** Он переключает вид только
    при фокусе в сетке/вертикальном просмотре; в `NSTextView`/TextBox он должен
    оставаться Tab. На Windows это `PreviewKeyDown` с проверкой фокуса, а не
    `KeyboardAccelerator` уровня окна.
39. **Подсказка ключа зависит от асинхронных метаданных.** Пока `tableMeta` не
    загружена, показывать «Уникальный ключ не определён», не пустую строку и не
    ошибку; обновлять после загрузки.
40. **Числовая проверка для подсказок: запятая — тоже десятичный
    разделитель.** `NumericText.isNumeric` принимает `.` и `,`; значения из
    русской локали вставляются в автодополнение без кавычек. Калькулятора и
    фильтра в приложении больше нет.
41. **Ключ хранилища — не «ключа нет».** Ошибка доступа/биометрии не повод
    создавать новый мастер-ключ; новый ключ — только при `not found` и пустом
    `secrets.json` (§4.6, §16.1).

## 15. Быстрый старт для Windows-разработчика

1. Прочитать §2–§4 и поднять sidecar вручную:
   `java -jar Resources/sidecar.jar` (собран `./Sidecar/build.sh`, `Main-Class:
   silver.dbooyvol.Main`), отправить `{"id":1,"method":"ping","params":{}}`.
2. Сделать минимальный клиент: процесс + NDJSON + `connect` + `query` + вывод
   строк. Убедиться, что значения приходят строками.
3. Портировать модели и файлы состояния; проверить чтение существующего
   `profiles.json`.
4. Собрать layout: дерево, вкладки, редактор, сетка, статус-бар.
5. По одному добавлять §6–§7, сверяя поведение с macOS-версией.
6. Реализовать §16: вертикальную строку и Tab, кнопку «Результат (Tab)»,
   автодополнение SQL, ключ и подсказки с задержкой 1,0 с. Это проще делать
   после того, как сетка уже умеет выделение/копирование/экспорт.
7. Подключить локализацию и горячие клавиши.
8. Прогнать §12.2 на SQLite-фикстуре, затем на PostgreSQL.
9. Только после этого — Oracle, SSH, упаковка и подпись.

Этого документа вместе с исходниками достаточно, чтобы воспроизвести продукт.
Если поведение в коде расходится с текстом — **источником истины является код**;
текст описывает контракт и объясняет, что нельзя потерять.

### 16.1. Хранилище паролей и идентичность приложения (1.0.122–1.0.124)

macOS-реализация (`Sources/Model/Storage.swift`, `SecretStore`):

- `secrets.json` + мастер-ключ 256 бит в login Keychain,
  `service=silver.dbooyvol.secret-store`, `account=master-key-v2`.
- Шифрование AES-256-GCM, формат `enc2:<keyid>:<base64(nonce+ciphertext+tag)>`.
- `keyid` — первые 8 hex SHA-256 мастер-ключа; позволяет сравнить ключ с
  шифротекстом без расшифровки.
- `SecretStoreError` хранит `OSStatus`; отдельно различаются `keyMissing`,
  `wrongKey`, `authFailed`, `notFound`.
- `authenticate(reason:)` вызывает
  `LAContext.evaluatePolicy(.deviceOwnerAuthentication)` — Touch ID, а без
  биометрии пароль пользователя; **один раз за запуск** приложения.
- `keychainLoad(interactive:)` при отказе/ошибке доступа не считает ключ
  отсутствующим. `keychainAdd` используется только для создания, `keychainReplace`
  — только для явной ротации.
- `save`/`load` не перезаписывают ключ; `staleAccounts`/`hasStaleSecrets`
  находят профили, которые не расшифровываются текущим ключом; `diagnostics`
  отдаёт `keyid` и число stale.
- `rotateMasterKey` — единственная операция, создающая новый ключ и
  перешифровывающая все пароли.
- `Session.connectNow` сначала проходит биометрические ворота; при
  `wrongKey`/`keyMissing` `resolvePassword` не подставляет мусор, а предлагает
  восстановление.
- `AppModel.recoverStaleSecrets(for:)` показывает **один общий** диалог
  повторного ввода для всех пострадавших подключений, а не ошибку на каждое.
- Dev-флаг `--secrets-status` печатает `keyid`, `stale`, число профилей.
  В 1.0.124: `keyid=587559a8 stale=0`.
- Пароль в открытом виде живёт только до `connect`.

Windows-контракт: DPAPI (пользовательский контекст, без
`CRYPTPROTECT_LOCAL_MACHINE`) + AES-GCM с тем же форматом `enc2:`. Windows Hello
(`UserConsentVerifier`/`KeyCredentialManager`) — один раз за запуск. Ошибка
доступа — это не «ключа нет». Новый ключ — только при `not found` и пустом
`secrets.json`. Общий диалог восстановления. Ничего не логировать.

Идентичность приложения (не путать с миграцией данных):

- Bundle ID `silver.dbooyvol`, имя `DBooyvol`, ключи настроек и Keychain — только
  `silver.dbooyvol*`. Прежние идентификаторы `ru.evotor.sqldesk` (домен настроек
  и служба Keychain), `SQLDesk`, `DBuiwol` не используются; в Swift-коде они
  остались только в миграции старых данных (`Storage.swift`). Java-пакет
  sidecar при этом переименован в `silver.dbooyvol` (см. §2).
- В `AppSettings` вместо `defaultsMigratedFrom` остался флаг `defaultsMigrated`.
- На Windows имя каталога — `DBooyvol` (`%APPDATA%\DBooyvol`); не использовать
  старые имена, если планируется читать macOS-данные.

### 16.2. Локальный фильтр результата удалён

Фильтра в приложении больше нет — ни панели, ни однострочного поля, ни парсера
условий, ни подсказок колонок/операторов/значений, ни настройки

Что это значит для состояния:

- `dataRow(forDisplayRow:)` — тождественная функция (оставлена как единая точка

Вместо кнопки фильтра в статус-баре стоит кнопка **«Результат (Tab)»** —

### 16.5. Вертикальный просмотр одной строки (`Tab`)

Назначение: показать выбранную строку как одну строку таблицы — имя колонки
слева, значение справа; вся строка при этом одно выделяемое полотно.

Состояние:

- `@Published var showSingleRowResult` — по умолчанию `false`; сбрасывается при
  смене вкладки и при новом результате.
- `toggleSingleRowResult()` — требует непустой результат; переключает вид и
  ставит `focusedPane = .result`.
- `singleRowDisplayIndex` — первая выделенная строка (display), иначе 0.
- `singleRowItems() -> [SingleRowItem]` — по `result.visualColumnOrder`, с теми же
  заголовками, что и сетка (`resultHeaderTitle(for:)`), значения через
  `TimestampDisplay.formatted(_:columnType:)`, `nil` остаётся `nil`.
- `SingleRowItem { id: индекс колонки в visualColumnOrder, title, value: String? }`.

UI (`SingleRowResultView`):

- Заголовок: кнопка «Результат» (возврат), `Строка №N`, `из M`,
  подсказка «Tab — вернуться к таблице».
- Вся строка — один read-only `NSTextView` (`SingleRowText`): имена колонок в
  колонке 220 pt через табуляцию, значения моноширинным, `NULL` серым. Поэтому
  выделение мышью идёт поперёк колонок, `⌘A` выделяет всю строку, `⌘C`
  копирует выделенное; двойной клик — слово, тройной — содержимое литерала или
  скобок, как в панели значения.
- При открытии вида текстовое поле сразу получает фокус, так что `⌘A`/`⌘C`
  работают без клика; фокус не отбирается у редактируемых полей.
- Контекстное меню — стандартное текстовое (`Копировать`, `Выбрать все`) плюс
  `Экспорт → CSV… / XML… / XLSX…`; это те же действия, что у сетки, и они
  экспортируют результат (или выделение сетки), а не только показанную строку.
- `⌘A` в сетке выделяет все ячейки, как клик по углу над номерами строк; статус
  показывает `· выделено N×M`.
- Если строк нет — «Нет строк для показа».
- `Tab` переключает обратно. Локальный монитор клавиш игнорирует Tab, только
  когда first responder — **редактируемое** поле (`NSTextView`/`NSTextField` с
  `isEditable == true`), поэтому редактор и поиск работают normalmente, а
  выделенный текст в вертикальном просмотре Tab не блокирует.
- В сетке `GridTableView.keyDown` перехватывает Tab при фокусе в сетке.
- Переключение можно повторять **неограниченно**: каждый Tab меняет вид, и
  фокус не уходит в список подключений. После возврата в сетку
  `resultFocusPending` (одноразовый флаг в `AppModel`) восстанавливает first
  responder на таблице, иначе следующий Tab уходил бы в key-view loop окна.
- Кнопка **«Результат (Tab)»** в статус-баре (иконка
  `rectangle.split.2x1`, при включённом виде — `rectangle.split.2x1.fill`)
  вызывает ту же функцию; без результата она скрыта. Её подсказка — ровно
  `Результат (Tab)`, без дополнительного текста.

Windows: один read-only текстовый контрол (или `RichTextBox`/`TextBox` с
разметкой) на всю строку, чтобы выделение шло поперёк колонок, а `Ctrl+A`
выделяло всё; либо `DataGrid` из двух колонок с общей моделью выделения.
`PreviewKeyDown` на сетке и на этом просмотре; проверять, что фокус не в
редактируемом TextBox, иначе не перехватывать Tab. После возврата явно
возвращать фокус сетке. Контекстное меню — копирование/выделить всё плюс
экспорт CSV/XML/XLSX теми же командами, что у сетки.

### 16.10. Открытые ограничения (не забыть при переносе)

- Локального фильтра нет: отбор строк — только в SQL.
- Автодополнение значений ограничено 500 различными значениями и текущим
  результатом; полноценный словарь схемы не строится.
- Вертикальный просмотр показывает одну строку и не листает строки стрелками;
  чтобы выбрать другую, нужно вернуться в сетку.
- Подсказка ключа зависит от того, сообщил ли драйвер PK и загрузились ли
  метаданные.
