# Форматтер SQL

## Что это за форматтер

Это **собственный форматтер DBooyvol**, а не сторонняя библиотека
(не `sqlformat`, не `SqlFormatter` из NuGet, не форматтер DBeaver).
Он построен на уже существующем в проекте токенизаторе `SQLText` и меняет
**только пробелы и переводы строк**. Ни один токен не переписывается:
строковые литералы, dollar-quoted блоки PostgreSQL, комментарии, кавычки
идентификаторов и числа остаются байт-в-байт.

Причина: нужен предсказуемый результат для PostgreSQL, Oracle, ClickHouse и
SQLite одновременно, без диалектных сюрпризов и без тяжёлой зависимости.
Форматтер не пытается «понять» SQL грамматически — он работает с потоком
токенов и ключевыми словами, поэтому одинаково безопасен для любого диалекта.

## Как работает

1. **Токенизация.** Строки (`'...'`, `E'...'`, `$$...$$`, `$tag$...$tag$`),
   комментарии (`--`, `/* */`), идентификаторы в кавычках (`"..."`, `` `...` ``,
   `[...]`) и числа распознаются как неделимые токены.
2. **Разбиение на строки.**
   - `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `ORDER BY`, `HAVING`, `LIMIT`,
     `UNION`, `INSERT`, `UPDATE`, `DELETE`, `VALUES`, `SET`, `RETURNING`
     начинают новую строку.
   - Списки после `SELECT`, `GROUP BY`, `ORDER BY`, `VALUES`, `SET` идут
     по одному элементу на строку.
   - `AND` / `OR` выравниваются под `WHERE` / `ON` с дополнительным отступом.
   - Подзапросы в скобках получают свой уровень отступа.
   - `CASE` / `WHEN` / `THEN` / `ELSE` / `END` образуют блок.
3. **Сборка.** Между токенами расставляются пробелы по правилам
   (функция и её `(`, унарные операторы, запятые, точки), затем — переводы
   строк и отступы.
4. **Идемпотентность.** Повторное форматирование уже отформатированного текста
   даёт тот же результат — это проверяется тестами.

## Настройки

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `FormatterIndent` | 4 | ширина отступа |
| `FormatterUppercaseKeywords` | вкл | ключевые слова заглавными |
| `FormatterCommaFirst` | выкл | запятая в начале строки |
| `FormatterMaxWidth` | 120 | мягкий предел ширины |

Настройки находятся в «Вид → Настройки → Форматтер SQL» и сохраняются в
`settings.json`.

## Пример

До:

```sql
select a,b,c from users u where u.active=true and u.id>1 order by u.id desc;
```

После:

```sql
SELECT
    a,
    b,
    c
FROM users u
WHERE u.active = TRUE
    AND u.id > 1
ORDER BY u.id DESC;
```

Подзапросы, `CASE`, CTE и списки `VALUES` обрабатываются тем же способом;
точные примеры зафиксированы в `tests/DBooyvol.Core.Tests/SqlFormatterTests.cs`.

## Ограничения

- Форматтер не меняет регистр идентификаторов и не переименовывает ничего.
- Сложные vendor-расширения (например, `MODEL`, `CONNECT BY`, ClickHouse
  `FORMAT`) форматируются консервативно: переносы только по базовым ключевым
  словам, остальное сохраняется как есть.
- Ширина строки — мягкая: длинные неделимые токены не разрываются.
- Строковые литералы и комментарии никогда не переформатируются.
